# Security policy

## Reporting a vulnerability

If you find a security vulnerability in this repository—whether in the code, scripts, workflows, documentation, or any other component—please **do not** open a public GitHub issue.

Instead, report it privately to the **CCTS Platform Team** at:

> **<placeholder>**

Use a subject line that begins with `[SECURITY] <repository-name>`.

## What to include

Please include as much of the following information as possible:

- A description of the issue
- The repository path of the affected file(s) or component(s)
- Steps to reproduce the issue
- The potential impact
- Any suggested mitigation
- Whether you intend to disclose the issue publicly, and if so, your proposed disclosure timeline

## What happens next

The CCTS Platform Team will:

1. Acknowledge receipt within 5 working days.
2. Triage and assess the reported issue.
3. Work on a fix and coordinate disclosure with you.
4. Credit you in the release notes if you would like to be acknowledged.

We follow a coordinated vulnerability disclosure process. Please allow us a reasonable opportunity to investigate and remediate the issue before making it public.

## Supported versions

Security updates are provided for the latest version of this repository. If you believe an issue affects an older version, please report it anyway.

## Out of scope

The following are typically considered out of scope:

- Issues in third-party tools or dependencies (please report these to the relevant upstream project).
- Issues in downstream services or applications that use this repository.
- Theoretical issues with no practical exploitation path.

If you're unsure whether an issue is in scope, we'd still encourage you to report it. We'd rather investigate a false positive than miss a genuine security issue.
